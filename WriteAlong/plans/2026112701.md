## 3. Workstream 2 — True PDF-Like Paged Preview with Exact Print Parity

### 3.1 Architecture Choice: Purpose-Built `runtime/paginate.js` vs. Paged.js
We evaluated vendoring `pagedjs` (`0.4.3`, MIT, **5.9 MB** unpacked / ~300+ KB minified) against building a lean, deterministic pagination engine (`runtime/paginate.js`, ~12–16 KB minified):

| Criterion | Paged.js (`pagedjs`) | Dedicated `runtime/paginate.js` (Chosen) |
|---|---|---|
| Bundle weight inside every portable `read.html` | +300 KB × 110 templates (~33 MB bloat) | **~14 KB** (keeps `read-bundle.js` ~115 KB) |
| Multi-column (`--columns: 2`) + `column-span: all` | Known fragmentation bugs in Paged.js | **First-class deterministic 2-column & span-all band support** |
| Dark-paper `@page` backgrounds & per-page borders/grids | Fragile stylesheet rewriting | **Native per-`.wa-page` background, grid & frame styling** |
| Live editor re-render speed & zero flash | Slow (150–400 ms); mutates stylesheets destructively | **Fast (< 25 ms per 4-page doc), offscreen double-buffered swap** |
| Exact Screen ↔ Print-to-PDF Parity | Screen = `.pagedjs_page`, Print = same pages | **Screen = `.wa-page`, Print = exact same `.wa-page` 1-to-1 with `@page { margin: 0 }`** |

**Decision:** Build **`runtime/paginate.js`** as a first-class module in `runtime/`, bundled into `runtime/read-bundle.js` so the Editor preview, `read.html`, `Export PDF`, and `Export Standalone HTML` all use the **exact same paginated DOM**.

### 3.2 Unified Sheet DOM & Exact Print Parity Contract

Every rendered document produces discrete physical sheets inside `#wa-root`:

```html
<div class="wa-pages" data-page-count="4">
  <section class="wa-page" data-page="1">
    <div class="wa-margin-top">
      <div class="wa-margin-box wa-top-left"></div>
      <div class="wa-margin-box wa-top-center"></div>
      <div class="wa-margin-box wa-top-right"></div>
    </div>
    <div class="wa-page-content">
      <!-- Exact printable content box (W - mL - mR) × (H - mT - mB) -->
      <div class="wa-body" data-page-flow="1">...</div>
    </div>
    <div class="wa-margin-bottom">
      <div class="wa-margin-box wa-bottom-left"></div>
      <div class="wa-margin-box wa-bottom-center">Page 1 of 4</div>
      <div class="wa-margin-box wa-bottom-right"></div>
    </div>
  </section>
  <!-- .wa-page[data-page="2"], ... -->
</div>
```

**Why Screen and PDF Print Match Exactly:**
- **Geometry identity**: Every `.wa-page` has explicit physical CSS dimensions `width: var(--page-width); height: var(--page-height);`. Inside it, `.wa-page-content` sits at `top: var(--margin-top); right: var(--margin-right); bottom: var(--margin-bottom); left: var(--margin-left);` so its content box width and height are **strictly fixed in physical units** (`in`/`mm`).
- **Running headers & footers**: Parsed directly from the document's `@page` and `@page :first` margin boxes (`@top-left`, `@top-center`, `@top-right`, `@bottom-left`, `@bottom-center`, `@bottom-right`), including string literals, `counter(page)`, `counter(pages)`, `content: none`, font/color/border styles, and rendered as real DOM boxes inside `.wa-margin-top` and `.wa-margin-bottom`!
- **`@media screen`**: `.wa-pages` displays `.wa-page` sheets stacked vertically with `24px` gaps, realistic layered sheet shadows on the desk backdrop (`#dfe3ea`), and optional margin-guide outlines when `View → Page Grid` is enabled.
- **`@media print`**:
  - Emits `@page { size: <page-width> <page-height>; margin: 0 !important; }` (and strips native `@top-*`/`@bottom-*` margin boxes from the print stylesheet so headers/footers are never double-rendered!).
  - `.wa-pages` collapses padding/gaps to `0`; every `.wa-page` prints 1-to-1 with `break-after: page; break-inside: avoid; box-shadow: none; margin: 0; overflow: hidden;` (and `.wa-page:last-child { break-after: auto; }`).
  - Result: **Every line break, word wrap, column break, table header repeat, figure placement, running header, page number, and page count in PDF matches the on-screen preview 1-to-1.**

### 3.3 Pagination Engine Algorithm (`runtime/paginate.js`)

1. **Wait for true metrics**: Before measuring, await `targetDoc.fonts?.ready` and wait for all `<img>` elements inside the staging tree to decode (`complete` or `load`/`error` with timeout fallback).
2. **Parse `@page` configuration (`parsePageConfig(styleCss, meta)`)**:
   - Resolve `--page-size`, `--page-width`, `--page-height`, `--page-margin`, `--page-background`, `--columns`, `--column-gap`, plus explicit `@page { size: ...; margin: ...; }` overrides (handling `portrait` / `landscape` orientation keywords cleanly!).
   - Expand CSS margin shorthand (1, 2, 3, or 4 values) into `{ top, right, bottom, left }`.
   - Parse `@page` and `@page :first` margin-box blocks (`@top-left`..`@bottom-right`) and compile their `content` expressions (`"..."`, `counter(page)`, `counter(pages)`, `none`) plus inline style declarations (`font-family`, `font-size`, `color`, `letter-spacing`, `border-top`, `border-bottom`, `padding-top`, `padding-bottom`).
   - Emit sanitized print CSS (`stripNativeMarginBoxes(styleCss)`) so native Chrome `@top-*`/`@bottom-*` boxes do not collide with `.wa-margin-top` / `.wa-margin-bottom`.
3. **Offscreen Staging Measurement**:
   - Mount an invisible `.wa-measure-stage` inside `targetDoc.body` (`position: fixed; left: -20000px; top: 0; visibility: hidden; pointer-events: none;`) with exact printable width `W - mL - mR` (and exact column width `(contentW - colGap) / 2` for 2-column mode) so `getBoundingClientRect()` returns true rendered heights including margins, line-height, borders, and web fonts.
4. **Block-by-Block Flow & Fragmentation**:
   - **Cover page**: If `.title-block.cover` is present, place it on Page 1 (vertically centered inside `.wa-page-content`) and force a break to Page 2.
   - **Explicit page break (`.page-break`)**: Flush the current page (if non-empty) and open a fresh page; discard the marker so blank pages are never created.
   - **Atomic blocks (`break-inside: avoid`)**: `.title-block`, `.figure`, `.callout`, `pre`, `blockquote`, `.pull-quote`, `.sidebar`, `.toc`, `.no-break`, `.signature-block`. If `blockHeight > remainingHeight` and the current page already has content, move the whole block to the next page. (If an atomic block exceeds a full page's height on an empty page, allow it without infinite looping and constrain image `max-height` to printable height.)
   - **Keep-with-next headings (`h1`–`h6`, `break-after: avoid`)**: Compute the heading's height plus the minimum non-orphan height of its next sibling (e.g., ~2–3 lines of a following `<p>`, first `<li>` of a list, `<thead>` + first `<tr>` of a table, or an atomic follower). If the pair doesn't fit, push the heading onto the next page so **no orphaned headings ever appear at the bottom of a page**.
   - **Paragraph (`<p>`) splitting with `orphans` / `widows`**:
     - When a `<p>` overflows the remaining height, inspect line breaks using a DOM-preserving word-boundary splitter (supporting inline `<strong>`, `<em>`, `<code>`, `<a>`, `<sup>`, `<s>` cleanly via `Range` / clone-split).
     - Enforce `orphans >= 2` (or `3` when possible) on the current page and `widows >= 2` on the next page; if fewer than `orphans` lines fit, move the entire `<p>` cleanly to the next page.
     - Add class `.wa-fragment-cont` on continuation fragments (`text-indent: 0 !important;`) so book-style indented paragraphs don't falsely indent mid-sentence on Page 2.
   - **List (`<ul>` / `<ol>`) splitting**:
     - Append `<li>` items one by one until remaining height is exhausted; push remaining `<li>` items to a continuation list on the next page.
     - For `<ol>`, set `start="<nextIndex>"` on the continuation `<ol>` so numbering stays continuous (`1, 2, 3` → `4, 5`).
   - **Table (`<table>`) splitting**:
     - Keep `<thead>` + `<tr>` rows together row-by-row; when a row overflows, start a continuation `<table>` on the next page with a cloned `<thead>` at the top so multi-page tables always repeat column headers cleanly.
   - **Footnotes (`.footnotes`)**: Flow cleanly at the end of the document, splitting between `<li>` entries if needed while spanning full width in 2-column layouts.
5. **Two-Column (`--columns: 2`) Pagination**:
   - Partition body items into **full-width (`span-all`)** items (`.title-block`, `.toc`, `.footnotes`, `.page-break`, plus `table` and `.figure` when `column-span: all` is computed) and **columnar** items.
   - Render columnar segments inside `.wa-cols-2` (`display: grid; grid-template-columns: 1fr 1fr; column-gap: var(--column-gap); align-items: start;`).
   - Fill Column 1 up to `remainingHeight`, then Column 2 up to `remainingHeight`, then break to the next page.
   - When a `span-all` block arrives mid-page after columnar content, balance the two columns above it (using target height `ceil(totalSegmentHeight / 2)` capped at `remainingHeight`), emit the `span-all` block below (or on the next page if it doesn't fit), and continue cleanly.
6. **Pass 2 — Stamp Page Numbers & Margin Boxes**:
   - Once all `N` pages are finalized, populate every page's `.wa-margin-top` and `.wa-margin-bottom` boxes with resolved `counter(page)` (`1..N`) and `counter(pages)` (`N`), honoring `@page :first` overrides on page 1.
7. **Atomic DOM Commit (Zero Flicker)**:
   - Build the entire `.wa-pages` tree offscreen and swap `#wa-root` in a single frame, preserving `scrollX`/`scrollY` (clamped to new document height) and reporting `{ pageCount, currentPage }` back to the editor status bar!

### 4.2 New Sculpted Editorial Monogram Design
We will craft a genuinely refined **High-Contrast Modern Serif (Bodoni / Didot inspired) WA Ligature** using pure hand-tuned cubic Bézier `<path>` geometry (zero font dependencies):
- **Core Motif (Preserved & Elevated)**: The final ascending hairline stroke of **W** IS the first ascending stroke of **A** — sweeping seamlessly in one continuous razor-sharp diagonal from W's second lower vertex up to A's graceful pointed apex!
- **Optical & Typographic Refinement**:
  - **Consistent slant geometry**: Every diagonal shares an exact rhythmic angle (~17° off vertical), giving architectural harmony between all five strokes (`\ / \ / \`).
  - **High-contrast weight modulation**: Weighted primary downstrokes (W's 1st stroke, W's 3rd stroke, A's right leg) contrasted against refined hairlines (W's 2nd upstroke, the shared W→A upstroke, and A's crossbar) with subtle calligraphic flare at the joints.
  - **True bracketed concave serifs**: Flowing cubic Bézier (`C`) fillets that curve organically out of the stems into crisp horizontal serif feet/caps—never detached rectangles.
  - **Optical vertex overshoot**: Sharp mitered lower vertices of W and upper apex of A extend ~1.5% past the cap/baseline so the ligature reads level to the human eye.
  - **Refined A-crossbar**: Positioned slightly below geometric midline (~64% down) for classic Didone elegance, delicately joining the shared diagonal to A's thick right stem.

### 5.3 CSS Source-of-Truth Synchronization (`app/page-setup.js`)
Keeping `style.css` as the single source of truth (so hand-editing and `.wa` portability stay 100% intact):
- **`parsePageSetupFromCss(cssText)`**:
  - Reads `--page-size`, `--page-width`, `--page-height`, `--page-margin` from `:root`, falling back to `@page { size: ...; margin: ...; }` if `:root` omits them.
  - Detects named presets (`Letter`, `A4`, `A5`, `Legal`, `Executive`, `Tabloid`, `6in 9in`), detects `landscape` orientation (either via `landscape` keyword or `width > height`), and parses 1/2/3/4-value CSS margin shorthands into `{ top, right, bottom, left, unit }`.
- **`applyPageSetupToCss(cssText, setup)`**:
  - Computes canonical values:
    - Named preset + Portrait: `--page-size: Letter;`, `--page-width: 8.5in;`, `--page-height: 11in;`
    - Named preset + Landscape: `--page-size: Letter landscape;`, `--page-width: 11in;`, `--page-height: 8.5in;`
    - Custom dimensions: `--page-size: <w><u > <h><u>;`, `--page-width: <w><u>;`, `--page-height: <h><u>;`
    - Margins: `--page-margin: <top> <right> <bottom> <left>;`
  - Surgically updates those four properties inside `:root { ... }` (inserting any missing ones cleanly at the top of `:root`, or creating `:root` if absent) **AND** updates `size:` and `margin:` inside the main `@page { ... }` block (without disturbing `@page :first`, `@top-*`, `@bottom-*`, comments, or any user rules!).
  - Dispatches the update via `store.setCss(...)` + `editor.replaceCssOnly(...)` (preserving undo history in CodeMirror!), immediately re-paginates the preview iframe with the new size/margins/orientation, updates the status bar pill (`A4 · Landscape · 4 pages`), and queues IndexedDB autosave.

## 9. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Infinite pagination loop if a single atomic block (e.g., tall code block or image) exceeds a full page's printable height | Guard: if a page is already empty and the block still overflows, clamp `.figure img { max-height }` dynamically to printable height and place the block on the current page rather than spawning empty pages. |
| Browser sub-pixel rounding causes a `.wa-page` of exact `11in` height to spill 1px onto a blank trailing PDF page | Use `height: calc(var(--page-height) - 0.5px)` (or `overflow: hidden` with `box-sizing: border-box` and `break-after: page` except `:last-child`), verified across all 110 templates by asserting `screenWaPageCount === pdfPageCount`! |
| Paragraph splitting breaks inline HTML tags (`<strong>`, `<a>`, `<code>`) | Implement DOM-tree cloning / `Range`-based node splitting rather than naive `innerHTML` string slicing so tags always stay properly nested and valid. |
| Live typing feels laggy if pagination runs on every keystroke | Debounce preview re-pagination (~180 ms), skip re-pagination if text/CSS unchanged, and swap `.wa-pages` offscreen in a single frame with scroll position preserved. |
| Page Setup edits clobber custom user CSS or `@page` margin boxes | Write targeted brace-aware CSS updaters in `app/page-setup.js` that only modify `--page-*` inside `:root` and top-level `size:`/`margin:` inside `@page`, leaving nested `@top-*`/`@bottom-*` rules untouched. |
